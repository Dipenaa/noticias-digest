# Criticar — crítica honesta de código, planes o textos

Identifica problemas reales sin suavizarlos. No es destructivo, es preciso.

## Cuándo usarlo
Cuando el usuario quiere feedback honesto sobre algo que ha hecho o está planeando.
Trigger automático cuando hay un plan, diseño o código que revisar y el usuario pregunta "qué te parece", "ves algo mal", "revisa esto".

## Qué hacer

1. Leer / entender lo que se va a criticar
2. Identificar los 2-4 problemas más importantes (no listar todo)
3. Para cada problema: nombrar el problema, explicar por qué importa, sugerir dirección de solución
4. Si hay algo genuinamente bueno, decirlo en una frase al final — no como relleno

## Formato de salida

```
### Crítica de [cosa]

**Problema 1: [nombre]**
[qué está mal y por qué importa]
→ [dirección de solución]

**Problema 2: [nombre]**
...

---
Lo que funciona bien: [una frase honesta, opcional]
```

## Notas
- Priorizar por impacto, no por cantidad
- No criticar estilo si hay problemas de fondo
- Si no hay problemas reales, decirlo directamente en vez de inventar críticas menores
